# A Comprehensive Survey of LLM Agents and Tool Use Architectures, Scaling Paradigms, and Security Challenges

## TL;DR
- LLM agents combine foundation models with reasoning, planning, memory, and external tool execution to bridge natural-language intent and real-world software systems [1].
- Architectures are shifting from monolithic prompts and naive ReAct loops toward structured abstractions such as Monadic Context Engineering [2], Tool-Schema Hypergraphs [3], and global DAG planners [4].
- Recent scalability advances leverage self-play reinforcement learning, programmatic environment synthesis, and dynamic context/tool retrieval mechanisms like ToolScope [5] and Tool-R0 [6].
- Critical open challenges involve handling tool-environment unreliability [7], preventing indirect prompt injections across multi-skill and multi-agent workflows [8][9], and mitigating package hallucination attacks in agentic coding environments [10].

## Background
The paradigm of large language models (LLMs) has expanded from static text generation into autonomous, goal-directed AI agent systems [1]. Formally, an AI agent integrates a foundation model with core functional modules including reasoning, planning, memory, and external tool execution [1]. Recent survey analyses characterize this shift through a model-harness lens, moving from passive question answering to active task completion driven by advanced execution harnesses and context engineering [11]. Early systems relied on ad-hoc prompts and imperative execution loops that suffered from brittle state management, error handling failures, and concurrency bottlenecks. To address these limitations, recent theoretical frameworks formalize agent workflows using algebraic structures such as Monadic Context Engineering, which leverages Functors, Applicative Functors, and Monads to guarantee robust state transition and error recovery [2]. Furthermore, industry and academic analyses distinguish between "copilots"—router-worker architectures operating within a host application under step-by-step human confirmation—and fully autonomous "agents" capable of independent, multi-step workflow planning and execution [12]. Modular agent design has also embraced externalized procedural knowledge through componentized skill packages that load dynamically via progressive disclosure and standards like the Model Context Protocol [13].

## Core Architectural Paradigms and Decision-Making Backbones
To execute complex tasks, LLM agents require principled orchestration frameworks that go beyond basic text generation. Traditional ReAct (Reasoning and Acting) loops interleave thought generation with tool calls, but often degrade over long horizons due to error propagation and context clutter. To overcome this, recent architectures introduce advanced planning and reflection backbones. ReflAct embeds world-grounded decision making through continuous goal-state reflection, reducing hallucinations and aligning execution paths with desired objectives [14].

For complex multi-step tool composition, planner-centric frameworks replace reactive loops with global Directed Acyclic Graph (DAG) planners trained via Supervised Fine-Tuning and Group Relative Policy Optimization (GRPO) [4]. Similarly, HyperAgent structures tool relationships by constructing directed Tool-Schema Hypergraphs, overcoming the limitations of naive textual tool descriptions by explicitly modeling inter-tool dependencies at the schema level [3]. Frameworks such as AgentScope 1.0 provide unified developer-centric interfaces for deploying these single-agent and multi-agent applications reliably [15]. Operational safety is also integrated directly into the architecture; for instance, POLAR implements an ontology-guided risk prevention framework that assigns graded reversibility scores to actions through a two-layer invariant and runtime verification model [16]. At the infrastructure level, efficient serving of long-context reasoning agents is optimized by systems like KVTether, which manages KV cache lifecycles to reclaim dead entries and minimize prefill latency across subagent coordination [17].

## Scaling Paradigms, Self-Play, and Context Optimization
As agent workflows scale to tackle complex, multi-turn interactions, managing input context limits and acquiring robust tool-use behaviors without extensive manual annotation have become central research thrusts. ToolScope addresses input window constraints by combining a ToolScopeMerger—which automatically audits and corrects overlapping tool descriptions and redundancies—with a ToolScopeRetriever that selects only pertinent tools per query [5]. 

To overcome the bottleneck of scarce human-annotated tool interaction datasets, researchers have turned to automated environment synthesis and self-play. EnvScaler programmatically synthesizes diverse tool-interaction environments to train agents via supervised fine-tuning and reinforcement learning [18]. Extending this self-evolution philosophy, Tool-R0 enables agents to learn tool-calling policies entirely from zero initial data through self-play reinforcement learning [6]. Furthermore, Memento 3 enables frozen LLM agents to continually learn explicit world models through external memory and natural-language rulebooks, maintaining persistent semantic memory of revisable hypotheses [19]. For multi-step planning, ToolTree leverages Monte Carlo Tree Search combined with dual-feedback evaluation and bidirectional pruning to explore and optimize tool trajectories efficiently [20]. Additionally, long-horizon reinforcement learning scaling is supported by end-to-end summarization-based context management [21], supplemented by REMORY which uses residual memory tokens to compact contexts for frozen LLMs [22]. Specialized domains such as agentic black-box optimization (BBO) also benchmark LLM agents across mathematical, computational, and semantic task configurations [23].

## Benchmarks, Evaluation, and Environment Resilience
Evaluating LLM agents has traditionally assumed clean, deterministic, and trustworthy tool environments. However, recent benchmarks demonstrate that real-world deployment exposes agents to severe environmental volatility. ToolBench-X fills this gap by evaluating tool-using agents under recoverable reliability hazards across sequential, parallel, and mixed workflows, proving that standard function-calling models degrade significantly when APIs experience intermittent failures or unreliability [7].

Beyond technical failures, agent autonomy introduces significant security surfaces, particularly indirect prompt injection. ASPIRE establishes an open-ended vulnerability discovery engine using evolving Agent Security Behavior Graphs to detect indirect injection risks where agents retrieve untrusted data from web pages or files and inadvertently execute malicious tool calls [8]. In multi-skill routing environments, studies show that while injected third-party skills pose severe threats, realistic skill routers compel injected prompts to compete for selection, reducing attack success rates by 87–97% compared to static assumptions [24]. Conversely, training-time defense mechanisms such as RAISED attempt self-distillation for prompt-injection robustness, but often introduce severe utility degradation by causing models to refuse benign, authorized tool calls [25]. In software engineering domains, coding agents relying on shared community rule files (e.g., AGENTS.md or .cursorrules) are vulnerable to package hallucination attacks via PackHallu, where injected prompts induce agents to substitute legitimate dependencies with malicious attacker-controlled packages [10]. Furthermore, hierarchical multi-agent architectures reveal compositional security failures: runtime isolation policies like CaMeL provide strong single-agent guarantees, but these guarantees fail to compose when agents invoke other agents as tools [9]. Additional evaluation frameworks such as Intent-Eval examine agent vulnerabilities under evolving user intent in multi-turn dialogues where users propose and reject changes [26].

## Trends and Open Problems
Over the past two years, research in LLM agents has transitioned from heuristic prompt engineering to principled, algebraically grounded architectures and self-evolving reinforcement learning paradigms [2][6]. Despite these strides, several critical challenges remain unsolved or actively disputed:
- **Environment and API Robustness:** While benchmarks like ToolBench-X expose tool unreliability [7], achieving fault-tolerant agent execution across highly dynamic, stochastic enterprise APIs remains an open problem.
- **Security Compositionality:** As demonstrated in multi-agent systems, local safety guarantees (such as capability-based isolation) frequently collapse during hierarchical composition, requiring new formal verification models [9].
- **Defense-Utility Trade-off:** Training defenses against indirect prompt injection continue to suffer from catastrophic forgetting or excessive false refusals on benign tasks, highlighting the tension between security hardening and agent autonomy [25].
- **Context Scaling vs. Latency:** Although summarization, residual memory tokens (e.g., REMORY), and KV cache lifecycle management (e.g., KVTether) mitigate memory bloat [17][21][22], scaling multi-turn agent execution without incurring prohibitive latency or semantic drift is an ongoing architectural frontier.
